🐛 Root Cause: filteredArrayChildren Logic

Location: JsonTreeNode.vue, lines 459-498

The Problem:

  1. When checking if array items contain nested arrays, the code only checks paths starting with [0]
  2. Example: When at path "teams", it checks for "teams[0].members"
  3. But the actual arrayPaths contain "projects[0].teams[0].members"
  4. The path matching logic fails because it's not accounting for parent array indices

Specific Issue:

At line 475, the code builds:

const childPath = `${props.path}[0].${key}`

If props.path = "projects[0].teams" and key = "members":

childPath = "projects[0].teams[0].members"  ✓ Correct!

But when checking arrayPaths, it's looking for exact matches or startsWith patterns that may not account for the normalized paths used in filterToArraysOnly.

2. Improved Path Matching

The fix enhances the pattern matching in filteredArrayChildren to check:

// Check for ANY index [0], [1], [2], etc., not just [0]
const pathPattern = `${props.path}`
const keyToCheck = key

// Check if any arrayPath matches this structure
const matches = props.arrayPaths.some(arrayPath => {
  // Check for exact match like "projects[0].teams"
  if (arrayPath.startsWith(`${pathPattern}[`) &&
      arrayPath.includes(`].${keyToCheck}`)) {
    return true
  }

  // Check for deeper nesting
  if (arrayPath.includes(`${pathPattern}[`) &&
      arrayPath.includes(`.${keyToCheck}`)) {
    return true
  }

  return false
})
